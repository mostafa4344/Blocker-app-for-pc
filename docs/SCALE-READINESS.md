# ১ কোটি ইউজারের জন্য প্রস্তুতি — সৎ মূল্যায়ন (২৫ অক্টোবর ২০২৬)

## সংক্ষেপে
**এখনকার অবস্থা: ছোট পরিসরে বেটা (কয়েকশো থেকে কয়েক হাজার ইউজার) চালু করার মতো প্রস্তুত।
১ কোটির জন্য এখনো প্রস্তুত নয়।** মূল ব্লকিং আর ফাঁকি-প্রতিরোধ শক্ত, আসল PC-তে প্রমাণিত।
কিন্তু চারটি জিনিস না থাকলে বড় পরিসরে ছাড়া ঝুঁকিপূর্ণ:
১) অ্যাপের নিজে থেকে আপডেট, ২) code signing, ৩) স্বয়ংক্রিয় পেমেন্ট, ৪) সমস্যার খবর পাওয়ার ব্যবস্থা।

## 🔴 ১ কোটির আগে অবশ্যই লাগবে (গুরুত্ব অনুযায়ী)

### ১. অ্যাপের স্বয়ংক্রিয় আপডেট — **এখন একেবারেই নেই**
লাখো PC-তে কোনো বাগ পাওয়া গেলে ঠিক করে পাঠানোর উপায় নেই; প্রত্যেককে নিজে নতুন installer চালাতে হবে
(বেশিরভাগ ইউজার কখনো করবেন না)। **এটাই সবচেয়ে বড় ঘাটতি।**
প্রস্তাবিত নকশা (আমি বানাতে পারব):
- অ্যাপ দিনে একবার একটা ছোট "সর্বশেষ version" তথ্য দেখে।
- নতুন installer নামিয়ে **ডিজিটাল স্বাক্ষর যাচাই** করে, তারপর নীরবে আপডেট।
- স্বাক্ষরের গোপন চাবি শুধু আপনার কাছে (অফলাইনে) থাকবে — server হ্যাক হলেও কেউ ১ কোটি PC-তে ভাইরাস পাঠাতে পারবে না।
- ধাপে ধাপে ছাড়া (প্রথমে ১%, তারপর ১০%, তারপর সবাই), যাতে বাগ থাকলে অল্প কয়েকজনের ওপর পড়ে।

### ২. Code signing certificate
স্বাক্ষর ছাড়া Windows "Windows protected your PC" দেখায়; অনেকে সেখানেই থেমে যান।
আরও বড় ঝুঁকি: আমাদের অ্যাপ hosts ফাইল বদলায়, প্রোগ্রাম বন্ধ করে, ব্রাউজার-নীতি লেখে — এগুলো antivirus-এর
সন্দেহের তালিকায় থাকে। স্বাক্ষর ছাড়া কোনো antivirus একদিন হঠাৎ "ভাইরাস" বলে মুছে দিলে লাখো ইউজার একসাথে হারাবেন।
→ Certum (€২০৯) কিনুন; প্রতিটি release Microsoft-এর কাছে জমা দিন। `docs/EXTENSION-AND-CERTIFICATE-GUIDE.md`

### ৩. স্বয়ংক্রিয় পেমেন্ট
এখন Premium দিতে হয় হাতে (admin) বা কোড দিয়ে। দিনে হাজার হাজার ক্রেতা হলে এটা অসম্ভব।
দরকার: কার্ড/মোবাইল-ব্যাংকিং দিয়ে কেনা → server নিজে Premium চালু করবে (webhook)।
- আন্তর্জাতিক: Paddle বা Lemon Squeezy (এরা "merchant of record" — বিভিন্ন দেশের VAT/ট্যাক্স নিজেরাই সামলায়;
  বাংলাদেশ থেকে Stripe সরাসরি খোলা যায় না)।
- বাংলাদেশ: SSLCommerz বা bKash Payment Gateway (ট্রেড লাইসেন্স লাগে)।
- `supabase/functions/payment-webhook` টেমপ্লেট তৈরি আছে; অ্যাকাউন্ট খুললে আমি যুক্ত করে দেব।

### ৪. সমস্যার খবর পাওয়া (privacy বজায় রেখে)
এখন কোনো ইউজারের PC-তে অ্যাপ ভেঙে গেলে আপনি জানতেও পারবেন না।
প্রস্তাব: শুধু বেনামি তথ্য — version, Windows version, কোন ধাপে ভুল (error code) — কোনো ব্রাউজিং তথ্য নয়।
অ্যাপ এখনই দিনে কয়েকবার server-এ আসে; সেই অনুরোধের সাথেই "সব ঠিক আছে / অমুক সমস্যা" পাঠানো যায়।

## প্রস্তাবিত ধাপ
1. **এখন:** বেটা — ১০০–১,০০০ জন (পরিচিত, ফিডব্যাক দেবেন এমন)। Certificate কেনা শুরু করুন।
2. **পরের ২–৪ সপ্তাহ:** স্বয়ংক্রিয় আপডেট + সমস্যার রিপোর্ট (আমি বানাব), certificate দিয়ে সাইন, পেমেন্ট গেটওয়ে।
3. **তারপর:** load test, Supabase আপগ্রেড, ১০,০০০ → ১ লাখ ইউজার।
4. **১ কোটির আগে:** DNS-স্তরের ফিল্টার, macOS টেস্ট, সাপোর্ট ব্যবস্থা।

## এক্সটেনশনের ভবিষ্যৎ আপডেট — কীভাবে করবেন

### প্রতিবার আপডেটের ধাপ (৫ মিনিট + Google-এর ১–৩ দিন পর্যালোচনা)
1. `extension/manifest.json`-এ `"version"` বাড়ান (যেমন 1.1.0 → 1.2.0)। **আগের চেয়ে বড় না হলে Store গ্রহণ করে না।**
2. zip বানান (`dist/content-guard-extension.zip` — আমি প্রতিবার বানিয়ে দিই)।
3. Developer Dashboard → আইটেম → **Package → Upload new package** → **Submit for review**।
4. অনুমোদনের পর Chrome নিজেই কয়েক ঘণ্টার মধ্যে সব ইউজারের কাছে পৌঁছে দেয় — ইউজারকে কিছু করতে হয় না।

### কতবার আপলোড করতে হবে? — খুব কমই
আমি নকশাটা এমনভাবে করেছি যাতে **বেশিরভাগ পরিবর্তনে এক্সটেনশন আপলোড লাগে না**:
- কোন সাইট/শব্দ ব্লক হবে → desktop অ্যাপ বা Supabase থেকে আসে (আপলোড লাগে না)।
- প্রস্তুত লিস্ট বদলানো → Supabase টেবিলে (আপলোড লাগে না)।
- নতুন ভাষা, ব্লক পেজের নকশা, নতুন ব্রাউজার শনাক্ত করা → **শুধু এগুলোতেই** আপলোড লাগে।
বাস্তবে বছরে ২–৪ বার। কয়েকটা পরিবর্তন জমিয়ে একসাথে পাঠান।

### সাবধানতা
- **নতুন permission যোগ করবেন না** যদি না একান্ত জরুরি — permission বাড়লে Chrome সাধারণ ইউজারদের এক্সটেনশন বন্ধ
  করে অনুমতি চায়, অনেকে আর চালু করেন না। (জোর করে বসানো এক্সটেনশনে এই সমস্যা হয় না।)
- ১০,০০০-এর বেশি ইউজার হলে Dashboard-এ **ধাপে ধাপে ছাড়ার (partial rollout)** সুবিধা পাবেন: আগে ১০%-কে দিন, সমস্যা না হলে সবাইকে।
- আপলোডের আগে আমি টেস্ট চালাই আর পুরনো version-এর সাথেও desktop অ্যাপ কাজ করে কিনা নিশ্চিত করি
  (যেমন আজ: পুরনো 1.0.0 এক্সটেনশনও নতুন অ্যাপের সাথে চলে)।
- **চাইলে স্বয়ংক্রিয়:** Chrome Web Store-এর অফিসিয়াল API দিয়ে এক কমান্ডে আপলোড + জমা দেওয়ার স্ক্রিপ্ট বানাতে পারি।
  এর জন্য আপনার Google Cloud-এ একবার একটা OAuth চাবি তৈরি করতে হবে (চাবি শুধু আপনার PC-তে থাকবে)।
